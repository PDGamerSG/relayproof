# Glossary

Terms used in the RelayProof code and docs, with the file where each one is defined. Paths are relative to the repository root.

| Term | Meaning | Defined in |
| --- | --- | --- |
| Shadow traffic | A sampled copy of live chat-completion requests that the plugin replays against cheaper models after the primary answer has gone back to the caller. Callers never see a shadow answer, and a full queue drops shadow work instead of slowing live traffic. | `bifrost-shadow/plugins/shadow/main.go:1-15` |
| Source model (primary) | The provider and model whose live traffic an experiment copies. The answer it gave the caller is the reference every candidate is compared with. An empty provider or the model `*` matches any. | `bifrost-shadow/plugins/shadow/config.go:45-49`, `bifrost-shadow/plugins/shadow/config.go:73-74` |
| Candidate | A model that answers the copied requests in the shadow and is scored against the source model. | `bifrost-shadow/plugins/shadow/config.go:75-76` |
| Experiment | One source model, its list of candidates, an optional name and an optional sample rate of its own. A config needs at least one. | `bifrost-shadow/plugins/shadow/config.go:69-79`, `bifrost-shadow/plugins/shadow/config.go:197-198` |
| Sample rate | The share of eligible requests the plugin copies (default 0.1). Each request is decided with a random draw, so two runs never sample the same requests. | `bifrost-shadow/plugins/shadow/config.go:17`, `bifrost-shadow/plugins/shadow/config.go:195-196`, `bifrost-shadow/plugins/shadow/main.go:394` |
| `x-bf-shadow` header | On a request, `off` never mirrors it and `force` always mirrors it, but `force` only works when the operator sets `allow_force_header`. On a response, `sampled` marks a request that was mirrored. | `bifrost-shadow/plugins/shadow/main.go:45-51` |
| Judge | An optional LLM that scores the primary and candidate answers from 1 to 10, shown in random A/B order. With the default tolerance of 1 point, a candidate passes if it scores at most 1 point below the primary. | `bifrost-shadow/plugins/shadow/judge.go:12-31`, `bifrost-shadow/plugins/shadow/config.go:81-93`, `bifrost-shadow/plugins/shadow/worker.go:248-251`, `bifrost-shadow/plugins/shadow/worker.go:331` |
| Pass basis | The signal that decided a pair: `tool_selection` and `json_schema` (required checks that fail the pair), then `judge`, `exact`, `tool_arguments`, `semantic`, `lexical` (only when opted in), or `unscored` when no signal could decide. | `bifrost-shadow/plugins/shadow/worker.go:199-221`, `bifrost-shadow/plugins/shadow/worker.go:238-271` |
| Agreement | Passes divided by scored comparisons plus candidate errors. A candidate error counts as a failure. An unscored pair counts toward neither. | `bifrost-shadow/plugins/shadow/store.go:678-683` |
| Wilson lower bound | The low end of the 95% Wilson score interval (z = 1.96) around the agreement rate. Readiness uses this bound, not the raw rate, so a short lucky streak does not promote a model. | `bifrost-shadow/plugins/shadow/compare.go:397-412` |
| Verdict | The readiness label on a scorecard. `collecting`: fewer scored samples than `min_samples` (default 20). `not_ready`: error rate above `max_error_rate` (default 5%), judge error rate above `max_judge_error_rate` (default 10%), or agreement below `min_agreement` (default 90%). `ready`: the lower bound is at or above `min_agreement`. `promising`: the rate clears the bar but the lower bound does not yet. There are no other verdicts. | `bifrost-shadow/plugins/shadow/store.go:457-462`, `bifrost-shadow/plugins/shadow/store.go:733-758`, `bifrost-shadow/plugins/shadow/config.go:23-29` |
| Override reason | The text needed to promote a candidate whose verdict is not `ready`. It is stored on the rollout event, and the console asks for at least 8 characters. | `bifrost-shadow/transports/bifrost-http/handlers/shadow.go:219-220`, `bifrost-shadow/plugins/shadow/rollout.go:109-112`, `bifrost-shadow/site/src/live/Dialogs.tsx:100` |
| Dry run | A promotion with `dry_run: true`. It returns the routing rule, warnings and ramp it would write, and writes nothing. | `bifrost-shadow/transports/bifrost-http/handlers/shadow.go:221-222` |
| Canary | A candidate that gets a weighted share of its source model's live traffic through a routing rule that promotion created. The rule name starts with `Shadow canary: `. | `bifrost-shadow/plugins/shadow/rollout.go:219-236`, `bifrost-shadow/plugins/shadow/api.go:155-159` |
| Canary health | `watching` (fewer live candidate requests than `canary.min_requests`, default 20), `healthy`, or `unhealthy` (a guard limit is breached). | `bifrost-shadow/plugins/shadow/rollout.go:43-55` |
| Canary guard | A background check, every 5 seconds by default, that compares each canary's live error rate (its 95% Wilson lower bound) and p95 latency with the source model's. With `canary.auto_rollback` on it rolls a breaching canary back, and by default it also rolls back when the verdict turns `not_ready`. It also moves ramps forward. | `bifrost-shadow/plugins/shadow/rollout.go:50-77`, `bifrost-shadow/plugins/shadow/rollout.go:858-873` |
| Ramp | An optional plan in a promotion: 2 to 20 ascending traffic shares (`steps`), a minimum number of candidate requests per step (`min_requests`, at least `canary.min_requests`) and a minimum time per step (`hold_seconds`, default 60, at most 7 days). The guard moves the canary to the next step only while it is healthy. | `bifrost-shadow/plugins/shadow/rollout.go:33-38`, `bifrost-shadow/plugins/shadow/rollout.go:124-168` |
| Rollback | Taking a candidate out of its canary rule so the source model gets its share back. An operator does it with `POST /api/shadow/rollback` (event `rollback`). The guard does it on its own (event `auto_rollback`). | `bifrost-shadow/transports/bifrost-http/handlers/shadow.go:313-386`, `bifrost-shadow/plugins/shadow/rollout.go:21-31` |
| Rollout log | The list of `promote`, `rollback`, `auto_rollback`, `ramp` and `ramp_complete` events. Each event records who acted (`api` or `canary_guard`), the reason, the scorecard and the live health. It keeps the newest 500 events and, with `persist_path` set, saves them to `<persist_path>.rollouts.json`. | `bifrost-shadow/plugins/shadow/rollout.go:96-122`, `bifrost-shadow/plugins/shadow/rollout.go:54`, `bifrost-shadow/plugins/shadow/rollout.go:383-400` |
| Daily budget | `daily_budget_usd` caps what candidate, judge and embedding calls may spend per UTC day (0 means no cap). Today's spend survives a reset, a plugin reload and, with `persist_path`, a restart. | `bifrost-shadow/plugins/shadow/config.go:209-210`, `bifrost-shadow/plugins/shadow/ledger.go:19`, `bifrost-shadow/plugins/shadow/api.go:108-111` |
| Config store | Bifrost's own database (SQLite by default, which needs cgo). It holds routing rules, so without it promotion and rollback answer `503`. | `bifrost-shadow/scripts/setup.sh:12`, `bifrost-shadow/transports/bifrost-http/handlers/shadow.go:231-233` |
| Front door | The only public listener of the hosted demo. It forwards an allowlist of `/api/shadow/*` routes with the setup token attached, serves the `/api/demo/*` controls, rate-limits POSTs, and rolls back canaries older than 30 minutes. | `bifrost-shadow/examples/shadow-demo/frontdoor/main.go:1-28`, `bifrost-shadow/examples/shadow-demo/frontdoor/main.go:276-310` |
| Fault proxy | A proxy between the gateway and the real provider that fails a chosen share of one model's requests with HTTP 529 while an incident is set, so the hosted demo can show a rollback on real models. | `bifrost-shadow/examples/shadow-demo/faultproxy/main.go:1-12` |
| Mock upstream | A deterministic OpenAI-compatible server that plays `gpt-4o`, `gpt-4o-mini`, `llama-3.1-8b`, the judge `judge-1` and an embedding model, so the demo needs no API keys. `POST /admin/incident` makes a model fail with HTTP 503. | `bifrost-shadow/examples/shadow-demo/mockupstream/main.go:1-15` |
| Load generator (`loadgen`) | The demo client that replays the mixed dataset through the gateway, waits for the shadow queue to drain and prints the scorecard. `-report -require-ready` exits 2 unless a candidate is ready. | `bifrost-shadow/examples/shadow-demo/loadgen/main.go:51-85` |
| Setup token | The secret a Bifrost gateway with a config store and no dashboard login requires on `/api` calls, sent as `X-Bifrost-Setup-Token`. The demo scripts set one through `BIFROST_SETUP_TOKEN`. | `bifrost-shadow/examples/shadow-demo/run.sh:25-28`, `bifrost-shadow/examples/shadow-demo/dev.sh:21`, `bifrost-shadow/api/README.md:67-71` |
| Virtual key | Bifrost's per-caller governance key. The plugin's `virtual_keys` list limits mirroring to requests made with those keys, and shadow calls are internal requests that are never billed to the caller's key. | `bifrost-shadow/plugins/shadow/config.go:211-212`, `bifrost-shadow/plugins/shadow/main.go:667-690`, `bifrost-shadow/plugins/shadow/main.go:11-14` |
| Trial | The live console's default mode, connected to the hosted demo through the site's own origin. The other mode, Sign in, connects to your own gateway. | `bifrost-shadow/site/src/live/backend.ts:1-16`, `bifrost-shadow/site/src/live/Connect.tsx:30-34` |
